# Coordination workspace

Mode: Operate. Extend the existing light and green visual system using the approved single-workspace outline; code-led implementation of a specified application structure, without replacing its visual identity.

## First viewport

A narrow repository sidebar, compact repository breadcrumb and environment strip, objective title and acceptance checklist, a four-step state indicator, three agent work plans, and a right-hand event timeline. No marketing hero. At conflict, the shared-file ownership matrix leads the workspace and becomes the primary focus.

## Signature interaction

The user applies a project-memory-backed coordination plan in the labeled simulation. All three agents initially target `src/auth/session.ts`; the shared module remains with the API agent while UI and telemetry move to separate files. The UI waits for the authoritative scope updates, then for three submitted ChangeSets; accepting the plan alone never completes review.

## Boundaries

The local coordinator API is authoritative for demo state, including file conflicts and scope reassignment. Repository file previews remain illustrative excerpts, while submitted file paths and agent-reported tests are persisted in the coordinator ChangeSets. Identity and memory evidence identify the mock/cache adapter source. Keep real sponsor-provider integration outside this frontend milestone.

## Composition and behavior

- Desktop: 216px sidebar, flexible main workspace, 300px activity rail; collapse the rail below content on compact desktop and stack the three agent cards on mobile.
- Sidebar destinations: Workspace, Repository, Project memory, Integrations. Workspace tabs: Workstreams, Changes, Convergence.
- One green primary action per phase. Muted controls remain available for reset and evidence inspection. Reset requires confirmation only after progress exists.
- Drawer for secondary evidence, with focus restoration and Escape support. Keyboard-accessible tabs and navigation; reduced-motion support; visible focus and status announcements.
- Verification and memory source labels remain visible in all views. Never use a green live-integration badge for demo data.

## Validation

Test reducer transitions and completion gates, then inspect desktop/mobile, full demo, file inspection, reset, backend-disconnected state, and keyboard overlay behavior. Record remaining sponsor dependencies in the handoff.
